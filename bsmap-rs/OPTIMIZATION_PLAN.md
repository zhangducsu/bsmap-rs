### 2.2 P4-2: 索引查找预取优化

**问题**: 索引查找时存在大量cache miss。

**优化方案**: 软件预取优化。

| 优化项 | 描述 | 预期收益 |
|--------|------|---------|
| 预取KmerLoc2 | 提前加载index2条目 | 减少L2/L3 miss |
| 预取positions | 提前加载位置数据 | 减少主存访问 |
| 循环展开 | 展开查找循环 | 提高流水线效率 |

**实施位置**: `reference/index.rs`, `align/extend.rs`

**代码示例**:
```rust
#[inline(always)]
unsafe fn lookup_with_prefetch(index: &KmerIndex, hash: u32) -> &[u32] {
    // 预取下一个hash的索引条目
    let next_hash = hash.wrapping_add(1);
    if next_hash < index.total_kmers {
        prefetch!(index.index2.as_ptr().add(next_hash as usize));
    }
    
    let entry = &index.index2[hash as usize];
    // 预取positions
    prefetch!(index.positions.as_ptr().add(entry.start as usize));
    
    &index.positions[entry.start as usize..entry.end() as usize]
}
```

### 2.3 P4-3: 比对引擎向量化

**问题**: 当前比对是逐种子处理，未利用数据并行。

**优化方案**: 批量处理多个种子。

| 优化项 | 描述 | 预期收益 |
|--------|------|---------|
| 批量Mismatch检测 | 同时检测多个位置 | 2-4x加速 |
| 分支预测优化 | 减少分支开销 | 10-20%提升 |
| 循环融合 | 合并连续循环 | 减少循环开销 |

**实施位置**: `align/extend.rs`, `align/mismatch.rs`

---

### 2.4 P4-4: 配对算法优化

**问题**: 当前配对使用双重循环，O(n²)复杂度。

**优化方案**: 使用哈希表加速配对查找。

| 优化项 | 描述 | 预期收益 |
|--------|------|---------|
| 哈希表索引 | 构建read_a命中的哈希表 | O(n) → O(1)查找 |
| SIMD距离计算 | 批量计算insert size | 2-4x加速 |

**实施位置**: `pairs/pair.rs`

**代码示例**:
```rust
struct PairIndex<'a> {
    hits: &'a [GHit],
    index: HashMap<(u32, u8), Vec<&'a GHit>>,  // (chr, strand) -> hits
}

impl<'a> PairIndex<'a> {
    fn build(hits: &'a [GHit]) -> Self {

        for hit in hits {
            index.entry((hit.chr, hit.strand)).or_insert_with(Vec::new).push(hit);
        }
        Self { hits, index }
    }
```

### 2.5 P4-5: 内存分配深度优化

**问题**: 当前仍存在较多临时分配。

**优化方案**: 全面使用对象池和预分配。

| 优化项 | 描述 | 预期收益 |
|--------|------|---------|
| 线程本地对象池 | 减少锁竞争 | 减少分配开销 |
| Arena分配器 | 批量分配同类型对象 | 减少碎片 |
| 栈上缓冲区 | 小对象栈上分配 | 零分配 |

**实施位置**: `align/pool.rs`, `align/engine.rs`, `pairs/pair.rs`
