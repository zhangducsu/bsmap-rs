## 差异详情

### 差异 1: QNAME 后缀 (19,400 条)

| C++ BSMAP | Rust bsmap-rs |
|-----------|---------------|
| `1_NC_001416.1:3437-3764` | `1_NC_001416.1:3437-3764_R1` |

**原因**: Rust 在加载双端读段时为 R1/R2 追加了 `_R1`/`_R2` 后缀以区分正反读段。

**影响**: 低。下游工具通常不依赖 QNAME 后缀，但需要确保 R1/R2 配对能正确匹配。

**修复建议**: 在双端读段加载时保留原始 QNAME，不追加后缀。

### 差异 2: RNAME (19,400 条)

| C++ BSMAP | Rust bsmap-rs |
|-----------|---------------|
| `NC_001416.1` | `chr1` |

**原因**: Rust 使用 FASTA 文件中的染色体名称（`chr1`），C++ 使用 Accession（`NC_001416.1`）。与单端比对中已修复的 @SQ Header 问题同类。

**影响**: 中。RNAME 不一致会导致下游工具无法正确关联比对结果与参考序列。

**修复建议**: 与单端修复一致，在输出时只使用 Accession 部分。

### 差异 3: FLAG (19,400 条)

存在两种差异模式：

#### 模式 A: 0x10 位翻转 (9,734 条)

| C++ FLAG | Rust FLAG | XOR | 含义 |
|----------|-----------|-----|------|
| 83 | 67 | 16 | R1: C++ 有 rev，Rust 无 rev |
| 163 | 179 | 16 | R2: C++ 无 rev，Rust 有 rev |

**分析**: 对于 `-+` 和 `--` 链的配对（共 9,734 条），C++ 和 Rust 对 R1/R2 的 0x10 (SEQ reverse) 标志设置相反。C++ 在 R1 设置 0x10，Rust 在 R2 设置 0x10。

#### 模式 B: 0x20 位翻转 (9,666 条)

| C++ FLAG | Rust FLAG | XOR | 含义 |
|----------|-----------|-----|------|
| 99 | 67 | 32 | R1: C++ 有 mate_rev，Rust 无 mate_rev |
| 147 | 179 | 32 | R2: C++ 无 mate_rev，Rust 有 mate_rev |

**分析**: 对于 `++` 和 `+-` 链的配对（共 9,666 条），C++ 和 Rust 对 R1/R2 的 0x20 (mate reverse) 标志设置相反。

**根因**: Rust 双端输出的 FLAG 计算逻辑与 C++ 不一致。C++ BSMAP 的 FLAG 0x10/0x20 设置基于实际的链组合（ZS tag），而 Rust 的实现可能没有正确处理双端配对的链信息。

### 差异 4: POS (9,734 条)

| C++ POS | Rust POS | 关系 |
|---------|----------|------|
| 3615 | 44739 | 不匹配 |
| 3437 | 44917 | 不匹配 |

**分析**: 9,734 条记录的 POS 不匹配（恰好对应模式 A 的 FLAG 差异数量）。这些是 `-+` 和 `--` 链的配对，Rust 的坐标转换逻辑可能在双端模式下有问题。

### 差异 5: PNEXT (9,734 条)

与 POS 差异同源。Rust 报告的 mate 位置不正确。

### 差异 6: TLEN (9,734 条)

**特征**: 所有 TLEN 差异都是**符号翻转**（C++ TLEN = -Rust TLEN）。

**分析**: TLEN 符号翻转表明 Rust 对"哪条读段在上游"的判断与 C++ 相反。这与 POS 差异一致——当 POS 报告错误时，TLEN 的符号自然也会翻转。

### 差异 7: SEQ (9,734 条)

与 POS/FLAG 差异同源。当 FLAG 的 0x10 位设置相反时，SEQ 的输出方向也随之相反。

## 差异关联分析

所有差异可归结为**两类独立问题**：

### 问题 A: QNAME 后缀 + RNAME (格式问题)

影响全部 19,400 条记录，属于输出格式问题，不影响比对逻辑。

### 问题 B: 双端链处理逻辑 (核心逻辑问题)

影响 9,734 条记录（`-+` 和 `--` 链配对），涉及 FLAG、POS、PNEXT、TLEN、SEQ 五个字段。

**关键发现**: 4,833 条 `++` 和 `+-` 链配对中，POS 和 SEQ 完全一致，但 FLAG 的 0x20 (mate reverse) 位不同。这表明问题不仅限于反向链，而是双端 FLAG 计算的整体逻辑与 C++ 不一致。

## 已修复的 Bug

本次测试过程中发现并修复了以下 Bug：

### Bug: read_start 共享导致双端比对完全失败

**文件**: `bsmap/src/main.rs` 第 583-592 行

**问题**: `reader_a` 和 `reader_b` 共享同一个 `read_start` 变量。`reader_a` 读取一批记录后更新 `read_start`，导致 `reader_b` 跳过所有记录，双端比对输出 0 条。

**修复**: 为 `reader_a` 和 `reader_b` 使用独立的 `read_start_a` 和 `read_start_b` 变量。

**效果**: 双端比对从 0 条恢复到 9,700 条配对。
