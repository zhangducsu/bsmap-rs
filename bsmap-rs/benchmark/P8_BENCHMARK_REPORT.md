# BSMAP-rs P8 优化基准测试报告

**日期**: 2026-05-21
**结果目录**: `results_p8_20260521_074711/`
**P7 对比基线**: `results_p7_20260521_055015/`

---

## 概述

P8 根据 P7 报告 6.2 节建议进行了四项优化。本报告提供 C++ BSMAP vs P7 Rust vs P8 Rust 三路对比。

| 优化项 | 描述 | 状态 |
|--------|------|------|
| P8-1 | 修复 FLAG=0x800 多余标志位 | 完成 |
| P8-2 | 修复 2 条漏比对 read | 部分完成 (1/2) |
| P8-3 | .bsi 索引复制到 ext4 加速加载 | 完成 |
| P8-4 | 对齐 unique/multiple 统计口径 | 完成 |

---

## 测试配置

- **参考序列**: chr22 尾部 1Mbp (`chr22_tail_1M.fa`)
- **Ex1**: WGBS SE 75bp 10x (66,120 reads)
- **Ex2**: WGBS PE 150bp 10x (33,479 pairs)
- **硬件**: 16 CPU 核心
- **参数**: `-s 16 -v 0.08 -I 4 -p {1,4}`

---

## 1. 比对正确性对比

### 1.1 Ex1 SE p=1 比对行数

| 版本 | 比对行数 | vs C++ diff | 差异 |
|------|---------|-------------|------|
| C++ BSMAP | 66,120 | — | 基线 |
| P7 Rust | 66,118 | 4,902 行 | 漏 2 条 read |
| **P8 Rust** | **66,119** | **3,184 行** | **漏 1 条 read** |

- P7→P8: 恢复 1 条 read（read 446），diff 减少 1,718 行
- 剩余 1 条缺失（read 58512）: 全 T k-mer (`0x01486BA0`) 被 bisulfite 频率过滤器排除，已知限制

### 1.2 P7→P8 差异分析

P7 与 P8 SAM 输出差异全部为 FLAG 字段变化（P8-1 修复）:

| 变化 | P7 FLAG | P8 FLAG | 含义 |
|------|---------|---------|------|
| ++链多重比对 | 2304 (0x900) | 256 (0x100) | 移除多余 0x800 |
| +-链多重比对 | 2320 (0x910) | 272 (0x110) | 移除多余 0x800 |

### 1.3 Ex2 PE（C++ 崩溃，仅 Rust 对比）

C++ BSMAP 在 PE 模式存在 buffer overflow 崩溃（已知 bug），SAM 输出 0 行。P7 和 P8 Rust 结果完全一致（66,957 行，diff=0），PE 路径未受本次修改影响。

## 3. Unique/Multiple 统计对比 (Ex1 SE p=1)

| 指标 | C++ | P7 Rust | P8 Rust |
|------|-----|---------|---------|
| 比对数 | 66,120 | 66,118 | 66,119 |
| 唯一比对 (unique) | 64,951 (48.7%) | 55,948 | **64,884** |
| 多重比对 (multiple) | 1,169 (0.9%) | 10,170 | **1,235** |

- P7 unique 被严重低估（少 9,003 个），P8 修复后仅差 67
- P7 multiple 被严重高估（多 9,001 个），P8 修复后仅差 66

**根因**: P7 的 `is_unique_hit()` 跨所有 mismatch 层去重统计，导致大量只有唯一最佳匹配的 read 被误判为 multiple。C++ 语义是只看最佳（最低 SNP）层的命中数。

## 4. 性能对比

### 4.1 耗时 (Elapsed Time)

| 测试 | P7 (NTFS) | P8 (ext4) | 加速比 |
|------|-----------|-----------|--------|
| Ex1 SE p=1 | 21.93s | **4.73s** | **4.6x** |
| Ex1 SE p=4 | 16.65s | **4.23s** | **3.9x** |
| Ex2 PE p=1 | 18.45s | **6.12s** | **3.0x** |
| Ex2 PE p=4 | 18.33s | **5.91s** | **3.1x** |

### 4.2 索引加载时间

| 阶段 | P7 (NTFS) | P8 (ext4) | 加速比 |
|------|-----------|-----------|--------|
| .bsi 加载 | ~14s | ~2s | **~7x** |

P8-3 优化（.bsi 复制到 WSL2 ext4 本地文件系统）是性能提升的主因。NTFS 通过 9p 协议挂载，内存映射（mmap）大文件时性能显著下降。

### 4.3 内存占用

| 测试 | P7 Max RSS | P8 Max RSS |
|------|-----------|-----------|
| Ex1 SE | ~1.86 GB | ~1.86 GB |
| Ex2 PE | ~1.86 GB | ~1.86 GB |

内存占用无变化（同一份索引，相同数据结构）。

## 5. 三路对比总结

### 5.1 正确性改进

```
比对行数: P7=66118 → P8=66119 (C++=66120, gap: 2→1)
FLAG正确率: P7=有0x800 → P8=无0x800 ✓
Unique分类: P7=55948(偏差9003) → P8=64884(偏差67)
Multiple分类: P7=10170(偏差9001) → P8=1235(偏差66)
```

### 5.2 剩余差异分析

P8 与 C++ 的 3,184 行 SAM diff 主要包含:

1. **1 条缺失 read** (58512): 全 T k-mer 在 bisulfite 索引中被频率过滤器排除。这是 `.bsi` 索引过滤策略的差异，非比对逻辑 bug。C++ 可能使用不同的 k-mer 频率阈值或不过滤全 T k-mer。

2. **67 条 unique 差异**: 已大幅缩小（P7: 9,003 → P8: 67），剩余差异可能来自:
   - C++ 使用 `_cur_n_hit + _cur_n_chit` 分段统计（两个独立数组）
   - Rust 将所有链的命中合并在同一 `hits[level]` 中
   - 边缘情况下的舍入差异

3. **排序差异**: SAM 输出排序可能因多线程不确定性略有不同。

### 5.3 性能总结

P8 实现了 **3-4.6x** 的墙钟时间加速，主要得益于:
- P8-3: ext4 本地文件系统上 mmap 索引加载（~7x 加载加速）
- 实际比对计算时间未变（~2s SE, ~4s PE），但索引 I/O 瓶颈完全消除
