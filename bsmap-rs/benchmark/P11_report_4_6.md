# P11-4~6 速度优化基准测试报告

**日期:** 2026-05-22  
**基线:** P9 (commit `2ac58f3`, "P7-P9优化完成") + P11-1~3 (内存优化)  
**测试数据:** chr22_tail_1M (1M bases), ex1_se75_10x (66,120 reads, SE 75bp)  
**环境:** WSL2, Rust release build, mimalloc

---

## 本次新增优化 (P11-4 ~ P11-6)

| 编号 | 优化项 | 修改位置 | 类别 |
|------|--------|----------|------|
| P11-4 | `batch_raw.clone()` → `mem::take` 消除深拷贝 | `main.rs:532,637-638` | 速度 |
| P11-5 | `mismatch_pattern` 新增计数版本消除 Vec 分配 | `mismatch.rs:341-456`, `gap.rs:152-248` | 速度 |
| P11-6 | 直接构造 GHit 跳过 ExtHit 中间层 | `extend.rs:23-87`, `engine.rs:241,269-274` | 速度 |

**P11-4**: 每批 50,000 reads 消除 ~15 MB 深拷贝（name + seq + qual），SE/PE 两路径均覆盖  
**P11-5**: `try_all_gaps()` 热路径中不再为 mismatch 位置分配 Vec，改为直接计数返回 u32  
**P11-6**: 移除 `ExtHit` 中间结构体，在种子扩展阶段直接 push `GHit`，消除 `into_iter().map(to_ghit).collect()` 转换

## CPU 利用率

| 版本 | p=1 CPU% | p=4 CPU% | 多核加速比 |
|------|----------|----------|-----------|
| C++ | 98% | 129% | 1.47x |
| P11-4~6 | 98% | 99% | 1.23x |

C++ p=4 的 129% CPU 说明它更有效地利用了多核。Rust p=4 仅 99% 说明并行瓶颈在 I/O 或同步开销。P11-14（PairAlign 并行化）可进一步改善。

## 结论

### P11-4~6 三项优化效果

| 指标 | P11-1~3 → P11-4~6 | 评价 |
|------|-------------------|------|
| 速度 p=1 | 2.25s → 1.73s (**-23%**) | 显著提升 |
| 速度 p=4 | 1.61s → 1.41s (**-12%**) | 显著提升 |
| 内存 | 573 MB → 558 MB (**-15 MB**) | 边际改善 |
| 正确性 | 66,120 reads (一致) | 无回归 |
| SAM 差异 | 与之前一致 | 无新增差异 |

### vs C++ BSMAP

- p=1: **仅慢 4.2%**（1.73s vs 1.66s），基本持平
- p=4: 慢 24.8%（1.41s vs 1.13s），多核扩展仍有差距
- 内存: **低 36%**（558 MB vs 872 MB）

### 建议

P11-4~6 可以安全合入。P11-5 和 P11-6 的加速效果在更大数据集（全基因组）上会更加明显，因为 gap 比对和种子扩展的调用次数与 reads 数成正比。
