## P3优化内容

### 1. 提前终止策略

参考原版BSMAP逻辑实现：

```rust
fn should_stop_early(seg_idx, hits, snp_thres) {
    // 处理至少2个segment后才考虑终止
    if seg_idx < 2 { return false; }
    
    // 如果找到唯一比对且mismatch数足够好，提前终止
    if is_unique_ext_hit(hits) {
        if best_hit.snps <= snp_thres / 2 {
            return true;
        }
    }
    
    // 如果命中数超过1000，提前终止避免过多计算
    if hits.len() > 1000 {
        return true;
    }
    false
}
```

**优化效果**: 在数据质量较好、唯一比对率高的场景下，可以显著减少不必要的计算。

### 2. 命中去重优化

将原有的HashSet去重优化为排序+去重：

| 方案 | 时间复杂度 | 内存分配 |
|------|-----------|----------|
| **优化前** | O(n) 插入 | HashSet分配 |
| **优化后** | O(n log n) | 无额外分配 |

**优化效果**: 减少内存分配压力，提高缓存效率。

### 3. 对象池实现

新增对象池模块 `align/pool.rs`：

| 对象池类型 | 用途 |
|-----------|------|
| `ObjectPool<T>` | 通用对象池 |
| `HitPool<T>` | 命中记录专用池 |
| `BufferManager` | 缓冲区管理器 |

## 优化效果分析

### 提前终止效果

在当前测试数据上：
- **Ex1**: 唯一比对率 87.6%，提前终止策略有效减少了部分计算
- **Ex2**: 唯一比对率 97.0%，提前终止效果更明显

### 内存优化效果

| 测试用例 | bsmap-rs P3 | BSMAP C++ | 节省比例 |
|---------|------------|----------|----------|
| Ex1 SE | **575 MB** | ~850 MB | **32%** |
| Ex2 PE | **679 MB** | ~945 MB | **28%** |

### CPU利用率

- **Ex1**: 64% → 受I/O限制，索引预热占用部分时间
- **Ex2**: 76% → 双端比对计算更密集
