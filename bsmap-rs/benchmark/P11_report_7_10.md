## 总结

1. **正确性:** P11-7~10 与 P11-4~6 输出完全一致（0 diff），编译通过，166 测试 0 失败
2. **内存:** 稳定在 558 MB（比 C++ 低 36%），P11-7~10 未增加内存开销
3. **速度:** p=4 场景下几乎持平（+1.4% 测量噪声范围内），p=1 有波动但属正常测量误差
4. **P11-9 降级跳过:** start_offsets.clone() 是一次性索引构建开销（172 MB），不影响比对常驻内存

### P11-7~10 三项优化的实际效果

- **P11-7:** 消除 quick_gap_check 中每调用 3 次 `vec![u64::MAX; N]` 分配，用静态常量替代
- **P11-8:** 预计算染色体 accession 名，消除每条记录 `split_whitespace().to_string()` 的解析开销
- **P11-10:** 消除 batch 处理阶段 `from_utf8_lossy().to_string()` 的双重 String 分配

这三项优化属于热路径微观优化，在 p=4 多线程场景下整体性能持平，边际增益被并行化分摊。代码质量提升（更少的分配、更清晰的语义）是主要收益。
